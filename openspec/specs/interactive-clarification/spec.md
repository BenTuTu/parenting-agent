# Interactive Clarification Specification

## Purpose

让 Agent 能在一次运行内向家长提出一个澄清问题并直接拿到答复，把"缺信息就得多聊一轮"变成回答内部的一步。工具可见性由宿主是否注入交互能力决定：交互式宿主（chat TUI）才看得到，一次性 CLI 与 HTTP 服务不受影响。界面始终提供自由输入的逃生口与跳过出口，答案来源对模型可区分。

## Requirements

### Requirement: 交互式追问工具

系统 SHALL 提供 `ask_user_question` 工具，使 Agent 能在一次运行内向用户提出一个澄清问题并获得答案：工具调用期间运行 SHALL 挂起，由宿主界面向用户呈现问题，用户作答后答案 SHALL 作为工具结果返回，Agent 在同一次运行内据此继续作答，无需用户重新发起一轮对话。

工具参数 SHALL 为单个问题（问题正文 + 可选的选项列表，每个选项含标签与可选说明）。工具 SHALL NOT 支持多选，SHALL NOT 支持单次调用提出多个问题。

#### Scenario: 单轮内完成追问与作答

- **WHEN** Agent 因缺少月龄信息调用 `ask_user_question` 且用户作答
- **THEN** 答案以工具结果返回，Agent 在同一次运行内继续完成回答
- **AND** 用户无需将答案重新组织为一条新消息发送

### Requirement: 按宿主交互能力门控工具可见性

工具 SHALL 仅在宿主通过运行上下文注入了交互回调（`askUser`）时对模型可见；未注入交互能力的宿主中，该工具 SHALL NOT 出现在下发给模型的工具列表里。

#### Scenario: 交互式宿主

- **WHEN** 宿主在发起运行时注入了 `askUser` 回调
- **THEN** 模型可以调用 `ask_user_question`

#### Scenario: 非交互式宿主

- **WHEN** 宿主未注入 `askUser` 回调（如一次性 CLI、HTTP 服务）
- **THEN** 模型的工具列表中不包含 `ask_user_question`，不存在调用它的可能
- **AND** 该宿主的既有行为不受本能力影响

### Requirement: 自由输入逃生口

宿主界面 SHALL 在模型给出的选项末尾自动追加一个"其他，我自己说"选项，使用户在任何一次追问中都能绕过枚举自由输入；该逃生口 SHALL 由界面保证，不依赖模型在参数中自行添加。当模型提供的选项列表为空时，界面 SHALL 直接进入自由输入。

#### Scenario: 选项之外自由输入

- **WHEN** 模型提供了若干选项且用户选择"其他，我自己说"
- **THEN** 界面切换为自由文本输入，用户输入的内容作为答案返回

#### Scenario: 无选项的开放式提问

- **WHEN** 模型调用工具时未提供任何选项（如询问出生日期）
- **THEN** 界面直接呈现自由文本输入，无需用户先选择"其他"

### Requirement: 答案来源可区分

工具返回结果 SHALL 区分三种情形：用户选中了模型给出的受控选项、用户通过逃生口自由输入、用户跳过了本次提问。自由输入的内容 SHALL 原样返回，工具 SHALL NOT 对其做校验或解析。

#### Scenario: 受控选项

- **WHEN** 用户选中模型给出的某个选项
- **THEN** 结果携带该选项标签，并标明其来自受控选项

#### Scenario: 自由文本

- **WHEN** 用户通过"其他，我自己说"输入了自然语言内容
- **THEN** 结果携带原始文本，并标明其为自由输入
- **AND** Agent 在据此调用下游工具前先向用户确认理解，不擅自将模糊表述转换为精确数据

#### Scenario: 用户跳过

- **WHEN** 用户选择不回答本次提问
- **THEN** 结果标明本次提问被跳过
- **AND** Agent 不再就同一信息继续追问，基于已有信息给出一般性建议
