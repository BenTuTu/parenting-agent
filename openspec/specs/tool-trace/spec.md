# Tool Trace Specification

## Purpose

把 Agent 的工具调用轨迹（名称、完整参数、结果摘要）作为可见内容输出给开发者，用于排查"它为什么答成这样"。面向开发者而非家长，因此默认关闭，各宿主按自身惯例开启：常驻交互界面用启动参数，HTTP 接口用请求字段。轨迹是既有流程日志之外的第二条消费通道，不改变日志本身的行为与格式。

## Requirements

### Requirement: 工具调用轨迹的采集口径

系统 SHALL 能将 Agent 的工具调用采集为轨迹记录，每条记录包含：工具名称、调用标识、完整的调用参数、以及结果摘要。参数 SHALL 完整保留（它表达模型的意图，是排查的关键信号）；结果 SHALL 以摘要形式呈现而非全量（部分工具返回数千字正文，全量输出会淹没回答）。

轨迹 SHALL 由 Agent 生命周期事件采集，SHALL NOT 改变既有流程日志（`attachFlowLogging` / `logStep`）的行为与格式——两者是同一份事件的两条独立消费通道。

#### Scenario: 采集一次结构化工具调用

- **WHEN** Agent 调用 `calc_age_stage` 并传入出生日期
- **THEN** 轨迹记录包含工具名与完整参数
- **AND** 记录包含该次调用的结果摘要

#### Scenario: 大结果不淹没回答

- **WHEN** Agent 调用 `read_wiki_page` 且返回数千字的文档正文
- **THEN** 轨迹中的结果以摘要呈现，不输出全文

#### Scenario: 既有流程日志不受影响

- **WHEN** 在启用轨迹的情况下运行一轮带工具调用的对话
- **THEN** `[agent-flow]` 流程日志的内容与格式与启用前一致

### Requirement: 默认关闭与逐宿主开启

工具轨迹面向开发者排查而非面向家长，因此 SHALL 默认关闭：未显式开启时，各宿主的输出与本能力引入前完全一致。开启方式 SHALL 符合各宿主自身的惯例——常驻交互界面通过启动参数开启，HTTP 接口通过请求字段逐请求开启。

#### Scenario: 默认不打扰

- **WHEN** 未开启轨迹，运行一轮带工具调用的对话
- **THEN** 对话输出中不出现任何工具轨迹内容
- **AND** 输出与本能力引入前逐条一致

#### Scenario: 逐请求开启互不影响

- **WHEN** 一个客户端开启轨迹发起请求，另一个客户端未开启
- **THEN** 只有开启的一方收到工具轨迹
- **AND** 未开启的一方的响应内容不受影响

### Requirement: 排除已有专属呈现的工具

已经拥有专属交互呈现的工具 SHALL NOT 再输出轨迹记录，避免同一次交互被重复呈现。具体地，追问工具（`ask_user_question`）的调用与结果由追问界面与答复消息完整承载，SHALL 从轨迹中排除。

#### Scenario: 追问不产生重复输出

- **WHEN** 已开启轨迹，且 Agent 发起一次追问并取得答复
- **THEN** 该次追问仅以提问界面与答复消息呈现
- **AND** 不额外输出该追问的工具轨迹，问题与答案各只出现一次
